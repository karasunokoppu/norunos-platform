# 要件定義書 (Requirements Definition Document)

## 1. はじめに

本書は、「Norunos Platform」開発プロジェクトにおける要件を定義したものである。本ドキュメントは、開発者および関係者が「どのようなアプリケーションを作成するか」という認識を共有することを目的とする。

## 2. プロジェクト概要

### 2.1. 目的

- タスク管理、スケジュール管理、情報収集（メモ・マインドマップ）を一元的に行えるプラットフォームアプリを構築する。
- 既存のElectron製アプリ等と比較し、圧倒的な低メモリ消費と高速な動作を実現することを目指す。

### 2.2. システムの規模・特徴

- **提供形態**: デスクトップアプリケーション（スタンドアロン）
- **対応プラットフォーム**: PC (主要Linuxディストリビューション、Windows、macOSを想定)、将来的にはAndroid等のモバイル対応も視野に入れる。
- **想定ユーザー数**: 個人利用（数名規模）

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能・パフォーマンス

- **低リソース消費**: 常時起動を想定し、メモリおよびCPU使用率を極力低く抑えること。Electron製アプリと比較して大幅な軽量化を目指す。

### 4.2. ユーザビリティ

- **モダンUI**: 透過効果、枠なしウィンドウ、独自タイトルバーを採用し、OSネイティブかつモダンな操作感を提供すること。

### 4.3. 運用・保守性

- **データ管理**: ユーザーデータはローカル（SQLiteおよびファイル）で完結し、バックアップや移行が容易であること。

### 4.4. 拡張性 (将来構想)

- **デバイス間同期**:
  - 将来的に複数デバイス間でのデータ同期を可能にする設計を行うこと。
  - 全エンティティにUUID/ULIDを付与し、分散環境での競合を最小化する。
  - コンフリクト時は「最終更新優先」ルールを採用する。
  - Road Map: ローカル完結 -> ZIPエクスポート -> ディレクトリ同期 -> WebDAV -> E2E暗号化

## 5. 用語定義

- **UUID/ULID**: 分散システム等で重複しない識別子を生成するための規格。
- **Note**: ファイルシステム上のMarkdownファイルを指す。基本的には1ファイル1ノートとする。
